# Raw ANSI captures of the original game

Byte-exact recordings of the original game's `WCCMMUD.DLL` (sha256 `e3085336…`) under MBBSEmu
v1.0-alpha-090826, telnet 2323, staged by `test/stage.sh` from
`dist/WCCMMUD_1.11p_DOS_MBBSEmu_v2.zip`. They are the Layer 3 oracle of the test plan;
`script.json` is the first input format of the
differential harness (T-019).

## Files in each scenario directory

| File | Contents |
|---|---|
| `script.json` | The script, with each step's `result` from the recorded run |
| `raw.bin` | Every byte the server sent, telnet negotiation removed and nothing else changed: CP437, ANSI, CR/LF exactly as sent. Several connections (disconnect-punish) are concatenated |
| `plain.txt` | `patterns.raw_to_lines(raw.bin)` joined with `\n`, plus one `>>> 'cmd'` line (Python `repr` of what was sent) before the line in which each send happened. Removing those lines gives `raw_to_lines(raw.bin)` exactly |
| `README.md` | Generated by `capture.py`: description, DLL hash, date, terminal size, character, behaviours exercised, mask hints, and the lines the pattern registry leaves `unknown` |

## `script.json`

```json
{
 "scenario": "fight-arena",
 "port": 2323,
 "naws": null,
 "description": "...",
 "character": {"user": "Aldric", "password": "aldric1", "name": "Aldric Stonebrook",
               "race": "Human", "class": "Warrior", "level": 1, "start": "..."},
 "behaviours": ["why"],
 "mask": [{"regex": "for \\d+ damage", "why": "RNG"}],
 "notes": ["..."],
 "steps": [ ... ],
 "captured": "2026-10-14 14:29",
 "dll_sha256": "e308533696e1e64c..."
}
```

- `naws`: `[columns, rows]` to answer the server's `DO NAWS` with; `null` refuses it like every
  other option (MBBSEmu then uses 80x24).
- `behaviours`: the easily-missed behaviours the scenario exercises, one line each; the
  capture README lists them.
- `mask`: regexes (on the decoded text) a comparer must mask before a byte comparison: RNG
  fields, the build stamp, the direction-name letter slots (`[A-Z ]\x08`), clocks, who is on.

### Steps

Every step is an object; `op` defaults to `send`.

| Field | Meaning |
|---|---|
| `op` | `send`, `connect` (open the telnet connection), `disconnect` (drop it), `sleep` |
| `send` | Text to send. A CR is appended unless `raw`. `\e`, `\r`, `\n`, `\t` are escapes; `{name}` is replaced by a variable set earlier |
| `raw` | Send the keys exactly (the creation editor is driven one key at a time) |
| `until` | Regex searched in the plain text (ANSI removed, backspaces applied) of the output since the send; the step ends when it matches |
| `until_cursor` | `"row;col"`: the step ends when the last `ESC[row;colf` received since the send is this one and 0.3 s pass with no output |
| `wait` | With neither of the above: end after this many seconds without output (default 1) |
| `timeout` | Give up after this many seconds (default 10) |
| `nowait` | Send and go straight on (flood) |
| `seconds` | `sleep`: how long; with `until`, end early on a match |
| `set` | `{name: regex}`: group 1 of the last match in this step's output becomes `{name}` |
| `if_unset` | Run the step only if that variable is not set yet |
| `required` | Stop the run if this step does not match |
| `note` | Free text |
| `result` | Written by the run: `offset` (byte offset in `raw.bin` when the step started; for a send, where its marker goes), `waited` (seconds), `matched`, `sent` (when `{name}` was substituted), `vars`, `skipped` |

The prompt regex used by the realm steps is `\[HP=-?\d+[^\]\n]*\]:`; the BBS steps wait for
`Username:`, `Password:`, `Make your selection` and `\[MAJORMUD\]:`.

## Recording and checking

```bash
tools/differential/vendor/test/stage.sh && tools/differential/vendor/test/run.sh orig
python3 -I tools/differential/vendor/play/capture.py tests/captures/fight-arena            # replays script.json, rewrites all four files
python3 -I tools/differential/vendor/play/capture.py tests/captures/fight-arena --readme   # only README.md
cargo test -p silvermere-testkit --test raw_to_lines                                        # every capture still parses
```

`capture.py` also leaves the session's own log in `logs/<ts>-capture-<scenario>/` next to itself
(not committed). A re-run changes the character (and so the next scenario's starting state);
characters are wiped only by re-staging.

## Used by the M1 tests (T-029)

`bin/silvermere/tests/m1_walk.rs` replays these against the in-process server (stock world
imported from the stock `.VIR` set (`silvermere_testkit::stock`), Aldric created through the
line-mode editor) and compares each step's output with the capture after masking
(`silvermere_testkit::capture_compare`: the capture's own `mask` list, wholly masked monster
lines dropped, event sequence and bytes).

| Capture | Steps used | Test |
|---|---|---|
| `entry-existing` | 4, 5 (`E`, Enter) | `entry_existing_matches_capture` |
| `disconnect-punish` | 12 (`E` after the dropped connection) | `entry_after_disconnect_shows_punishment` |
| `creation-line-mode` | 4-6 (race list, class list, lawful) | `creation_line_mode_reaches_realm` (the editor itself is not compared: the original game draws MBBSEmu's form) |
| `room-walk` | 5-28 (to the Small Pier; step 29 on holds a wandering guardsman's line) | `room_screens_match_captures`, `text_exit_borrow_skiff` |
| `status-screens` | 5-12 (`st exp i set spells health wealth keys`) | `status_exp_inventory_set_match_captures` |
| `flood-and-refusals` | the burst of steps 6-20 (counts only) | `flood_control_warns_at_8_drops_at_12` |

Routes: `tests/fixtures/routes/*.mp` (see its README), walked by `walk_slum_loop_titles_and_exits`
and `routecheck_loops_close_on_new_server`.

Command lines:

```
cargo test -p silvermere --test m1_walk
# the same scenarios against the original game, nightly (MBBSEmu container), one at a time:
python3 -I tools/differential/differential.py run --scenario m1/room-walk --report report
```

`routecheck.py` of the MBBSEmu test harness reads the world files and talks to no server, so the
telnet counterpart lives in the Rust test; the Python script itself needs the world JSON of
T-006 (`--world-json`), which silvermere does not vendor.
